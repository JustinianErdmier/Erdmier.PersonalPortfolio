.NET

I was first introduced to .NET when I attended Eleven Fifty Academy. There I learned C# and built applications using .NET Framework. After graduating, I started learning and using .NET Core and took a special interest in Blazor. Working with .NET feels very homely to me. I think C# is an amazing language that has really blossomed and been polished these last few years. It's elegant and beautiful. But more than that, I also love the .NET community. Our community is brimming with passionate, helpful members who are always willing to help and share their knowledge. I'm so grateful for every opportunity I get to work with them.

The thing I love most about .NET is its versatility. It can be used to build virtually anything from native and web applications; machine learning and AI; IoT and machine programming; and games to name a few. While I've dabbled in a few of these spaces, my career has been focused on web applications. I've built countless APIs and used both Razor Pages and ASP.NET's MVC framework. But I've dedicated my focus on Blazor, particularly.

Blazor is an astounding framework that lets you build rich, interactive web applications using C#. It's almost identical to React, but offers all the great features and tooling of C# and .NET. It can run as a server-side application, or it can be built on top of WebAssembly, which means it's blazing fast and can run on any device.

UI/UX Design

I have found that I am unique amongst most developers. I don't just enjoy working on the back-end (e.g., server-side development, database design, infrastructure, etc.). I also really love UI and UX design. A common theme with me is the prioritization of quality, and I wholly believe this extends to how my solutions look to and work for end-users. This means learning and understanding UI and UX best practices and processes; accessibility concerns; tools for designing and developing. Even for projects where I am not directly charged with designing the UI and UX, I always take pride in reviewing given designs and being vocal about things that might need to be changed.

When I start new projects, I like to start by wire-framing the UI. I find that this gives me a better understanding of how the backend needs to be designed and what kind of technologies I'll need to use (e.g., API Endpoints, caching, authentication, etc.). Once I've gotten a sense of how the app will look and work, I'll spend some time developing a more concrete design in Figma and/or Canva.

I try not to constrain myself to one particular technology or framework when implementing UI designs. I've dedicated myself to having a strong understanding in CSS, which has allowed me to easily understand how other technologies work and even troubleshoot them when they don't work as expected. For example, I wrote all the CSS for this site from scratch using BEM convention and Sass. I've also used Bootstrap and Tailwind CSS to build responsive, mobile-friendly UIs.
